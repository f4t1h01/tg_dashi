# tg_dashi — отчёт о посещаемости из выгрузки СКУД

Telegram-бот на [aiogram 3](https://docs.aiogram.dev/). Ему отправляют выгрузку системы контроля доступа
**«Passages through perimeter»** (.xlsx), а он отвечает готовым Excel-отчётом: дашборд с фильтрами,
посещаемость за месяц и список по дням.

Бот ничего не хранит: базы данных нет, файл обрабатывается в памяти и сразу уходит обратно в чат.

## Возможности

- **/start** — приветствие сразу на трёх языках (русский, узбекский, английский); дальше бот отвечает
  на языке Telegram-клиента пользователя.
- Отправка .xlsx → анимированный прогресс в одном сообщении (минимум 5 секунд; если к 50 % работа
  не закончена, полоска замедляется) → файл отчёта + краткая сводка в подписи.
- **/help** — как пользоваться, **/settings** — текущие правила расчёта.
- Отчёт полностью на формулах: фильтры и переключатели на листе «Сводка» пересчитывают всю книгу.
  Значения по умолчанию сохранены в файле заранее, поэтому цифры видны и в превью на телефоне.

## Быстрый старт (Docker)

Нужны: сервер или компьютер с [Docker](https://docs.docker.com/engine/install/) и Docker Compose v2,
доступ в интернет к `api.telegram.org`. Публичный IP, домен и открытые порты **не нужны**: бот сам
опрашивает Telegram (long polling).

**1. Создайте своего бота** — напишите [@BotFather](https://t.me/BotFather) команду `/newbot`
и скопируйте токен вида `1234567890:AA...`.

**2. Скачайте проект**

```bash
git clone https://github.com/f4t1h01/tg_dashi.git
cd tg_dashi
```

**3. Задайте секреты** — скопируйте шаблон и впишите токен:

```bash
cp .env.example .env
nano .env
```

Минимально нужен только `BOT_TOKEN=...`. Файл `.env` в git не попадает (он в `.gitignore`).

**4. Запустите**

```bash
docker compose up -d --build
```

**5. Проверьте**

```bash
docker compose logs -f bot
```

В логе должна появиться строка `Run polling for bot @<имя_вашего_бота>`. Откройте бота в Telegram,
нажмите **Start** и отправьте выгрузку. Контейнер запущен с `restart: unless-stopped`, поэтому
переживает перезагрузку сервера.

## Запуск без Docker

Python 3.12+.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # впишите BOT_TOKEN

set -a; source .env; set +a        # загрузить переменные из .env (bash/zsh)
python -m app.bot
```

В PowerShell вместо `source` задайте переменную вручную: `$env:BOT_TOKEN="..."`, затем `python -m app.bot`.

## Настройки (.env)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **Обязательно.** Токен от @BotFather |
| `ALLOWED_USERS` | пусто | Telegram ID через запятую, которым разрешён бот. Пусто — бот открыт всем. Чужому пользователю бот покажет его ID, чтобы его можно было добавить |
| `WORK_START` | `09:00` | Начало рабочего дня (приход позже — опоздание) |
| `WORK_END` | `18:00` | Конец рабочего дня (уход раньше — ранний уход) |
| `LATE_GRACE_MIN` | `0` | Допуск опоздания в минутах |
| `WORKDAYS` | `1,2,3,4,5` | Рабочие дни недели (ISO: 1 = Пн … 7 = Вс). Отсутствие в рабочий день — прогул |
| `TZ` | `Asia/Tashkent` | Часовой пояс контейнера (влияет только на время в логах) |

`WORK_START`, `WORK_END` и `LATE_GRACE_MIN` — это значения, с которыми отчёт открывается. В самом
Excel их можно поменять на листе «Сводка», и вся книга пересчитается.

После изменения `.env` перезапустите бота: `docker compose up -d`.

## Обновление, логи, остановка

```bash
git pull && docker compose up -d --build   # обновиться до свежей версии
docker compose logs -f bot                 # логи
docker compose restart bot                 # перезапуск
docker compose down                        # остановить и удалить контейнер
```

Логи ротируются автоматически (3 файла по 10 МБ). В них пишутся только имя отчёта и Telegram ID
пользователя, содержимое файлов не логируется.

## Формат входного файла

Ожидается стандартная выгрузка **«Passages through perimeter»**: первый лист, в шапке
`Begin date:` / `End date:`, затем таблица:

| Date | Department | Name | Personnel Number | Events: arrival | | leaving | |
|---|---|---|---|---|---|---|---|
| 05.10.2026 | Lab | IVANOV IVAN | 001 | 09:12 | KPP2 Turniket2 | 12:30 | KPP1 Turniket1 |
| | | | | 13:05 | KPP1 Turniket1 | 19:25 | KPP 1 Exit |
| | | | | (no) | | 20:10 | Dorm3 |

- Строка с датой и ФИО открывает день сотрудника. Следующие строки **без даты и ФИО** — его остальные
  входы и выходы за тот же день.
- `(no)` — события в этой половине пары нет.
- Заголовки распознаются и на русском (`Дата`, `Отдел`, `ФИО`, `Табельный номер`, `События`,
  `приход` / `уход`).
- Предел — 20 МБ (ограничение Telegram Bot API на скачивание файлов ботом).

## Что в отчёте и как считается

| Лист | Содержимое |
|---|---|
| **Сводка** | 10 KPI (сотрудники, рабочие дни, посещаемость, опоздания, отсутствия, ранние уходы, средние приход / уход / время на территории) и 4 графика: по дням, распределение времени прихода, по отделам, топ-10. Фильтры: отдел, сотрудник, период, показатель графика, рейтинг |
| **За месяц** | Таблица «сотрудник × дата» с приходом и уходом в ячейке, цветом статуса, итогами по сотруднику и по дню |
| **За день** | Список «сотрудник × день» с автофильтром: статус, приход и уход с точками, время на территории, минуты опоздания и раннего ухода, число проходов |

Правила:

- **Приход** — самый ранний проход за день в любую сторону: если первая отметка — выход, значит
  человек уже был на территории. **Уход** — последний выход за день.
- Точки делятся на три группы: КПП и турникеты (учитываются всегда), общежитие (`Dorm…`) и
  техпомещения (`… room`). Общежитие и техпомещения по умолчанию **не** учитываются; их включают
  переключателями на листе «Сводка».
- **Опоздание** — приход позже начала дня с учётом допуска. **Ранний уход** — уход раньше конца
  дня. Оба считаются только в рабочие дни.
- **Отсутствие** — рабочий день без единого учитываемого прохода. Проходы в выходной — статус
  «Работа в выходной».
- Список сотрудников берётся из самого файла. Если человек не появился ни разу за период, бот о нём не знает.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -q                         # тесты
python -m app.cli выгрузка.xlsx отчёт.xlsx  # собрать отчёт без бота
```

```
app/
  parser.py     разбор выгрузки СКУД
  analytics.py  строки «сотрудник × день», режимы учёта точек, статусы
  report.py     сборка Excel (XlsxWriter): формулы + заранее посчитанные значения
  progress.py   анимированный прогресс в Telegram
  i18n.py       тексты на ru / uz / en
  bot.py        хендлеры aiogram
  cli.py        запуск из командной строки
tests/          тесты на синтетических данных
```

Ветки: `test` — разработка, `deploy` — стабильная версия, в неё мержится проверенный `test`.
Чтобы держать на одном сервере тестовый и боевой экземпляры, нужны **два разных токена**, отдельные
env-файлы и имена проектов:

```bash
export ENV_FILE=.env.test COMPOSE_PROJECT_NAME=tg_dashi_test DEV=1
docker compose up -d --build
docker compose run --rm --no-deps bot python -m pytest -q
```

Реальные выгрузки содержат персональные данные: `*.xlsx` исключены из git, не коммитьте их.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `BOT_TOKEN не задан` при старте | Нет `.env` или в нём пустой `BOT_TOKEN`. Проверьте, что запускаете из папки проекта |
| `TelegramConflictError: terminated by other getUpdates request` | Один токен запущен в двух местах (два контейнера, сервер + локально). Оставьте один экземпляр или заведите второй токен |
| `TelegramUnauthorizedError` | Неверный или отозванный токен — получите новый у @BotFather |
| «Не найдена строка заголовков» | Это не выгрузка «Passages through perimeter» или первый лист другой |
| В Excel на «Сводке» нули | Файл открыт в программе без пересчёта формул. Откройте в Excel / Google Sheets / LibreOffice |

## English quick start

A Telegram bot that turns a «Passages through perimeter» access-control export (.xlsx) into an Excel
attendance report: filterable dashboard, monthly grid and daily list. No database, nothing is stored.

```bash
git clone https://github.com/f4t1h01/tg_dashi.git && cd tg_dashi
cp .env.example .env          # set BOT_TOKEN from @BotFather
docker compose up -d --build
docker compose logs -f bot    # wait for "Run polling for bot @..."
```

Then open your bot in Telegram, press **Start** and send the export file. See [Настройки (.env)](#настройки-env)
for the optional variables (`ALLOWED_USERS`, `WORK_START`, `WORK_END`, `LATE_GRACE_MIN`, `WORKDAYS`).
